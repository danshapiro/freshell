## Findings

`[P3] Drop create-time probe rows individually instead of all-or-nothing rejection — server/sdk-bridge.ts:109-130` (`normalizeSlashCommandRows`)
The function returns `null` on the first schema-invalid row, killing the whole payload. That is correct for `commands_changed` pushes (a partial payload must not clobber the prior catalog — the stated rationale), but the same function also handles the fire-at-create `supportedCommands()` probe where there is no prior catalog to clobber: one malformed SDK row (e.g. an empty/non-string name, the only field the coercion layer cannot repair) silently means claude/kilroy panes advertise no command menu until a mid-session push happens to arrive. The sibling module added by this same branch, `server/fresh-agent/adapters/opencode/commands-catalog.ts`, deliberately does the opposite — drops individual invalid rows so "one bad row must never nuke a whole 40+ row listing" — which is the behavior that also fits the probe path. Fix is small: keep whole-payload rejection for the push arm; filter invalid rows (or reuse a shared per-row normalizer) for the probe.
