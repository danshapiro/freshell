# Codex managed runtime

Freshcodex's managed Linux x64 workload uses Codex 0.164.0. The provider inventory in `docker/runtime/provider-versions.json` and the Docker build argument must agree. Other provider versions are independent.

`docker/runtime/codex-native-sandbox.json` declares the native package, helper, npm entrypoint and seccomp identity. Its provenance records the official default from the tested Docker daemon and the small set of namespace/mount rules required by Codex's bundled bubblewrap. The profile retains the default denials, architecture and capability conditions. It is selected only for the managed Codex executable; explicit custom terminal executables and other providers retain their existing policy.

The additional syscall rules apply inside the workload container. They do not configure the host or Docker daemon. The workload still has a read-only root, bounded mounts and resources, no new privileges and dropped capabilities; the provider runs with UID 65534 and GID 0. Native `never` approval with read-only or workspace-write sandboxing must independently deny forbidden file and network effects. An accepted `untrusted` approval can authorize Codex's native retry without sandboxing and is tested separately from `never` confinement.

The workload image installs the published npm package. Its build assembler verifies the npm entrypoint, native executable and bundled helper, normalizes permissions only in the owned package tree, and writes `/opt/freshell-codex/layout.json`. The managed launcher at `/opt/freshell-codex/launch` validates that layout and executes the stock npm entrypoint through the fixed image Node runtime. It prefixes the owned bundled-helper directory only in the child environment and supplies npm installation context. It does not change the installed entrypoint or global PATH. Missing helpers or an incompatible layout refuse launch. Rust checks final argument and environment sizes after this child environment expansion, before dispatch.

The supervisor passes the declared seccomp JSON to Docker and checks the inspected policy before start or reuse. Native, helper, wrapper and policy identities participate in runtime ownership. Existing containers built with a different identity require the existing replacement path; they cannot be adopted on labels alone.

Codex 0.164 rejects public `approval_policy = "untrusted"` before typed request overrides. Freshcodex preserves its declaring source through the owned prepared-config path, omits that rejected declaration only from prepared copies, then sends the intended native typed policy. Unsupported source selectors and native requirements that prohibit the policy produce an explicit configuration error before work. Original user files remain untouched.

To qualify a changed version, helper, wrapper or policy, use the Task 1 native harness. Connected preparation is `node scripts/testing/prepare-codex-contract.mjs --sandbox`; `--verify-sandbox` verifies completed prerequisites before networkless entry. The managed proof is `node test/integration/providers/codex-cli-contract.mjs --managed-runtime --receipt-dir ABSOLUTE_OWNED_PATH`. It builds an existing run-owned workload image, adds system requirements only in a disposable test derivative, and runs the native matrix through the installed npm wrapper as the provider identity. Artifact fixtures and version output alone do not qualify the managed runtime. Preserve raw scenario receipts, actual Docker inspection, image digest and denied-effect evidence. No production restart or deployment is part of qualification.
