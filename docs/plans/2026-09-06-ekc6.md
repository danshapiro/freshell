## User Request

### Requested result

Port `GET /api/fresh-agent/diff` to the Rust server, using the retired Node
route as the response-shape oracle, so expanding a file-change row in a
fresh-agent transcript renders the diff against the production (Rust) server.
Check AGENT-13's `POST /api/fresh-agent/exec` endpoint for the same gap and
close it with the same parity. Surface failures inline in the
`FreshAgentDiffPanel` instead of leaving it perpetually loading. Evidence:
crate-level tests pinning the response shapes, a fresh-agent diff-panel unit
test pinning the inline-error behavior, and a `rust-chromium` e2e spec that
exercises the panel against a real Rust server with the diff route
un-stubbed.

### Explicit constraints

- Response shapes, statuses, and error envelopes must be identical to the
  Node implementation (`server/fresh-agent-extras-router.ts`).
- The `server/` tree is frozen legacy: this change never modifies it and
  ports from it exactly.
- Every task's test must fail first (route returns 404 / test missing the
  behavior) before the implementation lands (`git commit` gates each task).
- All crate-level tests must be runnable via `cargo test -p freshell-server`
  and must be hermetic: tempdirs, no network, no touching `$HOME`.
- The e2e spec must run against a throwaway `RustServer` (ephemeral loopback
  port, mkdtemp HOME) — never against the live server on port 3001.
- Source-verification: `npm run check` (the supplied oracle command) must
  pass, honoring the three pre-existing baseline failures in
  `test/unit/vite-config.test.ts` (identity-keyed, not to be repaired here).
- Full QA gate (`freshell-qa.sh` = `npm run check` + `cargo fmt --all
  --check` + 3× clippy) must exit 0 before landing.

### Accepted tradeoffs and residuals

- Scope: only `/diff` and `/exec` are ported (AGENT-13's two missing routes).
  `/attachments`, `/send`, and `/checkpoints` are either already ported or
  out of this work item's scope.
- Node collapses spawn-error and signal-kill cases to `exitCode: 1` with an
  empty-output body; the Rust port does the same mapping explicitly rather
  than surfacing richer diagnostics, to preserve the frozen client contract.
- Truncation length arithmetic uses byte counts (UTF-8) where Node used
  UTF-16 code units; ASCII output is identical, and the divergence only
  matters at the exact 200KB truncation boundary of multi-byte text —
  documented in the module doc comment, same precedent as the AGENT-14
  checkpoints port.

**Goal:** `GET /api/fresh-agent/diff` and `POST /api/fresh-agent/exec` work on
the Rust server with byte-compatible response shapes, so the fresh-agent
"Files changed" diff panel stops failing against production and surfaces
inline errors instead of spinning forever.

**Architecture:** Add one new axum module
`crates/freshell-server/src/fresh_agent_extras.rs` following the established
`checkpoints.rs` (AGENT-14) port model: router function taking a small
`FreshAgentExtrasApiState` (auth token + boot-resolved home), handlers doing
`crate::boot::{is_authed, unauthorized}` gate checks, and hermetic in-crate
tests driving handlers directly. Register it in `main.rs` next to
`checkpoints` with state constructed as
`FreshAgentExtrasApiState { auth_token: Arc::clone(&auth_token),
home: Arc::new(home.clone().unwrap_or_else(|| PathBuf::from("."))) }`
(home is `Option<PathBuf>` at that point, exactly as `checkpoints_state`
consumes it at `main.rs:1550`; Task 1's diff handler ignores `home` — Task
2's exec handler uses it as the default cwd, mirroring Node's
`os.homedir()` fallback). Tests come first and pin the response-shape parity against
the Node oracle (lined-out in each task). A client-side unit test pins the
diff panel's error rendering (already present — never left spinning — now
test-pinned), and a `rust-chromium` e2e spec drives the real panel against
the real route.

**Tech Stack:** Rust/axum (tokio process), Vitest + Testing Library (client
unit), Playwright `rust-chromium` project + per-spec `RustServer` (e2e).

## Documented port divergences (planner-owned; bind the executor)

These are the faithfulness boundaries the load-bearing stage set; each has
ledger evidence (`logs_dir/load-bearing-ledger.md`, `reports/load-bearing-validator-*.md`):

1. **Malformed-JSON exec body**: Node serves express's HTML SyntaxError
   page (400, text/html, embeds absolute module paths — not byte-stable).
   Rust returns 400 `{"error":"invalid JSON body"}`. Good-faith clients
   (the SPA always POSTs JSON) never reach either.
2. **Non-JSON / empty exec body**: express skips parsing → 400
   `{"error":"command is required"}` — REPLICATED (custom body parse, no
   bare `Json` extractor).
3. **Duplicate `cwd` query key** on /diff: Node coerces the array to
   missing → 400 `cwd query parameter required`; axum rejects the parse →
   its own 400 text. Not replicated (edge; good-faith-unreachable).
4. **exec default cwd**: boot-resolved home (FRESHELL_HOME-aware, matching
   every other Rust state object and the isolation model) rather than raw
   `os.homedir()`; identical under every fixture, documented here.
5. **500 error suffix after the pinned prefix**: embeds live git stderr
   (git-version-specific usage page), identical mechanism to Node — pinned
   prefix `git diff failed: Command failed: git diff --no-color`, textual
   remainder floats with the installed git just as Node's does.
6. **Spawning `git`/`bash` missing from PATH**: suffix text is
   runtime-specific per platform by construction on both servers.
7. **Non-UTF-8 subprocess output**: lossy-decoded (U+FFFD replacement) —
   Node coerces via Buffer→string with the same replacement behavior.
8. **maxBuffer kill**: Node kills the child mid-stream on overflow; the
   Rust port drains with retained-output caps and maps to the SAME
   observable `exitCode: 1`, `truncated: true`, capped-output body (the
   child's wall-clock lifetime is longer; no response-shape difference).
9. **Truncation counting**: Rust counts UTF-8 bytes; Node counts UTF-16
   code units. Identical for ASCII; boundary differences only for
   multi-byte output at exactly the 200KB line (same accepted divergence
   class as the AGENT-14 checkpoints port documented).
10. **exec stdin** (execution-review resolution, Task 2 review I2): the
   child gets an always-open, never-written stdin pipe (mirroring Node
   execFile's default piped-stdin semantics — a stdin-reading command hangs
   until the 30s timeout, NOT an immediate EOF). Rust: `Stdio::piped()` and
   hold the handle without writing until after `wait()`; never
   `Stdio::null()`.
11. **exec content-type gate** (Task 2 review I1): only
   `application/json` (params allowed, case-insensitive) triggers JSON
   parsing — matching express `json()`'s default type test exactly.
   `application/*+json` vendor types are NOT parsed (falls into the
   missing-command 400), exactly like Node. Correction (delta-review R1):
   for non-object top-level JSON values, arrays AND objects reach Node's
   handler and produce the missing-command 400, while bare primitives
   (`5`, `"x"`) are rejected by express body-parser's strict mode with a
   400 HTML SyntaxError page BEFORE the route — the port treats all
   non-object values uniformly as the missing-command 400 (same status;
   body differs only for bare primitives, good-faith-unreachable).
12. **exec body size limit** (delta-review R1): Node mounts
    `json({ limit: '1mb' })` on the extras router, 413-rejecting exec
    bodies above 1MB; the Rust port parses via axum's `Bytes` extractor
    under the server-wide default body limit, accepting a 1-2MB command
    where Node refused — the same accepted deviation class recorded for
    earlier Rust ports. Unreachable by good-faith clients.

- Produces: `pub struct FreshAgentExtrasApiState { auth_token: Arc<String>,

**Diff parity contract (Node oracle `server/fresh-agent-extras-router.ts:304`
+ `runGitDiff` at its module top):**
- Missing/empty `cwd` query → 400 `{error: "cwd query parameter required"}`.
- `cwd` that does not exist on disk → 400 `{error: "cwd does not exist: <cwd>"}`
  (Node uses `fsp.access`, existence only — a file path passes and git fails
  later; replicate existence-only check).
- Else spawn `git diff --no-color` (+`-- <path>` when `path` given) in `cwd`,
  with `stdout`+`stderr` captured, 15s timeout, 512KB stdout cap
  (`DIFF_MAX_BYTES`); 200 `{diff: <stdout-as-utf8>}`. When the process errors
  AND stdout is empty → 500 `{error: <message>}` where the message is
  byte-shaped as
  `git diff failed: Command failed: git diff --no-color[ -- <path>]\n<git stderr verbatim>`
  — the Rust port SYNTHESIZES Node's execFile error-message wrapper
  (`Command failed: <joined commandline>\n<stderr>`) and embeds real git
  stderr unmodified (on this host, git 2.43 prints `warning: Not a git
  repository…` plus its usage page — git-version-specific; parity tests
  therefore assert the exact `git diff failed: Command failed: git diff
  --no-color` prefix + containment of the version-portable fragment
  `ot a git repository`, never the full body; oracle evidence:
  `logs_dir/reports/load-bearing-validator-A.md` case 4). A timed-out or signalled
  git with empty stdout maps to the same wrapper with whatever stderr was
  captured (empty stderr → `Command failed: git diff --no-color` alone).
  A spawn failure (git binary missing) yields Node's `spawn git ENOENT`
  text — replicated as `git diff failed: spawn git <io error text>`
  (documented divergence: suffix text is runtime-specific, prefix pinned).
- Nonzero git exit WITH nonempty stdout resolves 200 with that stdout
  (Node oracle: `if (error && !stdout) reject else resolve` —
  `server/fresh-agent-extras-router.ts:53-58`).
- Clean repo → 200 `{"diff":""}` (byte-exact).
- Query parsing (axum `Query<DiffQuery>`) accepts `cwd` + optional `path`.
  Documented divergence: a duplicated `cwd` key (`?cwd=/a&cwd=/b`) yields
  Node's 400 `cwd query parameter required` via query-array coercion, but
  axum's serde_urlencoded rejects it with its own 400 text — an edge no
  good-faith client produces; recorded, not replicated.
- Auth: missing/wrong token → 401 `{error: "unauthorized"}` body shape matches
  `crate::boot::unauthorized()`.

### Task 2: Rust `POST /api/fresh-agent/exec` — extend the same module

**Files:**
- Modify: `crates/freshell-server/src/fresh_agent_extras.rs`
- Test: same file

**Interfaces:**
- Consumes: `FreshAgentExtrasApiState` (now uses its `home` for default
  cwd), the capped-subprocess helper introduced in Task 1 Step 5.
- Produces: `POST /api/fresh-agent/exec` on the same router. Request JSON
  `{command: string, cwd?: string}`; response 200
  `{output, exitCode, truncated}`. Exact semantics (validator-A evidence):
  - Spawn is exactly `bash -lc <command>` via its own argv (never a shell
    string split) with the full inherited process env (Node: `env:
    process.env`), 30s timeout, 200KB combined-output cap.
  - `output` = `stdout` + (`stderr ? "\n" + stderr : ""`), trimmed — so
    stderr-only output has no leading newline (case 9).
  - `exitCode` = numeric process exit code; spawn failure, signal kill, and
    timeout all collapse to `1` (Node's `error.code` numeric-or-1 mapping).
  - Truncation: when combined output reaches the 200KB cap, `truncated:
    true` and `output` = the first 204800 units of combined +
    `\n[output truncated]`, with `exitCode: 1` (Node kills the child on
    maxBuffer → signal-kill collapse; case 12's byte-exact `seq 1 60000`
    evidence). The Rust port drains-and-caps rather than node-killing
    mid-stream, then maps to the same `exitCode: 1` / `truncated: true` /
    body — shape-identical, child lifetime slightly longer (documented).
  - Validation order (Node-first): missing/whitespace `command` → 400
    `{"error":"command is required"}` BEFORE the cwd existence check.
  - `cwd` omitted/empty → boot-resolved `home` (documented divergence:
    FRESHELL_HOME-aware, vs Node's raw `os.homedir()`; see L6).
  - Nonexistent `cwd` → 400 `{"error":"cwd does not exist: <cwd>"}`.
  - Body handling: replicate express's parse-skip — a missing, empty, or
    non-JSON-content-type body is treated as `{}` → 400 `command is
    required` (cases 13-14). A JSON content-type with malformed bytes
    returns 400 `{"error":"invalid JSON body"}` — DOCUMENTED divergence
    from Node, which serves express's HTML SyntaxError page (not
    byte-stable, good-faith-unreachable; case 15). Implement via `headers +
    axum::body::Bytes` extraction, not the bare `Json` extractor.
