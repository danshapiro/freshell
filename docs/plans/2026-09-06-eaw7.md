# Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a provider-agnostic, server-authoritative, per-session `statusSeq` on every status-bearing frame and snapshot, and make the client fold status only when the seq is strictly newer, so a stale snapshot after reconnect can never clobber a live `busy`/`running` state.

**Architecture:** The server (Node `sdk-bridge`/fresh-agent adapters and the Rust `freshell-freshagent` crate) mints a strictly monotonic per-session wall-clock-ms sequence at every tracked-status fold and stamps it on every emitted status-bearing frame, attach ack, and REST snapshot. The shared Zod contract carries it as an additive optional field. The client records `lastStatusSeq` per session in `freshAgentSlice` and drops any incoming status write whose seq is not strictly newer, atomically skipping `status`/`streamingActive`/`streamingText`; frames with no seq (pre-seq servers, untracked defaults) keep the legacy unconditional fold. Existing heuristics (`canAdoptSnapshotStatus`, `isStatusRegression`, `statusVersion`) remain as defense-in-depth.

**Tech Stack:** TypeScript (React/Redux Toolkit client; Node/Express server, NodeNext ESM with `.js` relative imports), Zod shared contract, Vitest; Rust (`freshell-freshagent`, `freshell-codex`, `freshell-ws` crates), cargo test/fmt/clippy.

## User Request

### Requested result

Work item as recorded for job `eaw7` (freshell): add a provider-agnostic, server-authoritative per-session `statusSeq` on every status-bearing frame/snapshot; the client folds status only when seq is strictly newer (mirroring the `nextMonotonicTurnCompleteAt` clamp regime), so a stale snapshot after reconnect cannot clobber busy.

### Explicit constraints

1. `statusSeq` is an optional integer (wall-clock milliseconds), strictly monotonic per session via the clamp `now <= last ? last + 1 : now` — the same regime as `nextMonotonicTurnCompleteAt`. It is not an ordinal counter.
2. Server-authoritative: the server mints at every tracked-status fold and stamps every emitted status-bearing frame, attach/snapshot ack, and REST snapshot with the tracked (status, statusSeq) pair.
3. Client-fold gate: fold iff `statusSeq > lastStatusSeq`; equal or older drops the entire status write atomically (status, streamingActive, streamingText skipped together; `statusVersion` bumps only on accepted writes). Missing or non-finite seq takes the legacy unconditional fold path so pre-seq servers keep working.
4. Restart safety: client baselines (`lastStatusSeq`) are cleared when `bootId`/`serverInstanceId` changes, dispatched beside `resetCompletionDedupeBaselines()`.
5. Never mint from untracked defaults: the claude disk-only `idle` fallback and hardcoded-idle Rust builders stay seq-less, with an explanatory comment.
6. Keep the existing client heuristics (`canAdoptSnapshotStatus`, `isStatusRegression`, statusVersion barrier) — defense-in-depth, never removed (LB-04).
7. Additive-optional wire changes only: no breaking change to `ws-fresh-agent-contract` or the rust-claude golden fixture pair; those stay seq-less by scope (LB-02).
8. Red/green/refactor TDD for every task; per-task commits; no plan-task may reduce or skip existing coverage.

### Accepted tradeoffs and residuals

1. LB-01 (mixed-version REST): `FreshAgentSnapshotSchema` is `.strict()`, and the REST lane strict-parses at `src/lib/api.ts:422-433`; `statusSeq` is added as `.optional()` following the deployed `commands` additive-optional precedent, so new servers tolerate old clients and vice versa. Residual: none expected beyond the precedent.
2. `statusSeq` uses wall-clock ms rather than a counter, so a server restart can re-mint from a lower clock value; the client compensates by clearing baselines on `bootId`/`serverInstanceId` change (constraint 4). Cross-restart staleness is therefore out of scope.
3. Rust codex seq state lives on `CodexSession` as `Arc<StdMutex<Option<i64>>>` threaded into `spawn_consumer` rather than inside the subscription task (LB-03: subscription task is task-private).
4. LB-05 residual closed by this plan existing; prior exploration notes live in untracked `.eaw7-scratch/`.
5. Out of scope: `docs/superpowers/plans/2026-06-23-fresh-agent-status-authoritative-followups.md` and `docs/index.html` are not edited.
