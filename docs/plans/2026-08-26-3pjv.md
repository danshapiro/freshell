## User Request

### Requested result
Clicking a link to a `.png` (or other image) file in Freshell opens the image
in a browser pane / image-viewer path instead of the Freshell editor.
Text/code file links continue to open in the editor exactly as before.

### Explicit constraints
- File-link routing detects image files by extension and/or MIME type.
- `.png` opens in a browser/image viewer path instead of the editor.
- Existing editor behavior remains unchanged for text-like files.
- Add focused coverage for `.png` link routing.

### Accepted tradeoffs and residuals
- None stated by the work item. Tradeoffs chosen by this plan (viewer = the
  existing browser pane over a new pane kind; new sandboxed `/api/files/raw`
  endpoint over the unsandboxed `/local-file` lane) are documented under
  Architecture and Global Constraints.

**Goal:** Clicking an image file link in a terminal opens the image in a
browser image-viewer pane — bytes served correctly-MIME'd and sandboxed —
while text/code links keep the unchanged editor flow.

**Architecture:**
Detection happens client-side where the click is routed today: the xterm
file-path `ILinkProvider` in `TerminalView.tsx`. A new `isImageFilePath`
predicate in `src/lib/path-utils.ts` classifies the matched path by
extension; on a hit, `activate` splits a **browser pane** whose URL is the
new same-origin `GET /api/files/raw?path=<enc>` endpoint instead of an editor
pane. Both servers (Node `server/files-router.ts`, Rust
`crates/freshell-server/src/files.rs`) gain `/api/files/raw`, which resolves
the path through the *same* machinery as `/api/files/read` (tilde expansion,
flavor-aware normalization, live `allowedFilePaths` sandbox → 403) but
returns raw bytes with the send-compatible `Content-Type` table already
vendored for `/local-file` (`image/png`, etc.), so an iframe renders the
image inline. Browser panes pointing at raw-file URLs get a meaningful
basename pane title via `derivePaneTitle`.

**Tech Stack:** React 18 + Redux Toolkit + xterm.js client (TypeScript),
Node/Express server (TypeScript, NodeNext/ESM), Rust axum server
(`freshell-server`), Vitest (default jsdom config + server node config),
supertest, cargo test/fmt/clippy.

```ts
/**
 * Extensions the client routes to an image viewer. Deliberately aligned with
 * the `image/*` entries of the servers' send-compatible byte-lane MIME table
 * (crates/freshell-server/src/files.rs `local_file_content_type`), so
 * `/api/files/raw` labels exactly these correctly.
 */
const IMAGE_EXTENSIONS = new Set([
  'png', 'jpg', 'jpeg', 'gif', 'webp', 'ico', 'bmp', 'avif', 'svg',
])

/**
 * True when the final segment of a file path (absolute, tilde, relative, or
 * Windows) ends in a known image extension, case-insensitively. Dotfiles
 * like `/x/.png` have no extension and return false.
 */
export function isImageFilePath(filePath: string): boolean {
  const segment = filePath.split(/[\\/]/).pop() ?? ''
  const dot = segment.lastIndexOf('.')
  if (dot <= 0) return false
  return IMAGE_EXTENSIONS.has(segment.slice(dot + 1).toLowerCase())
}
```

In `server/files-router.ts`, directly after the `/read` route:

```ts
  /**
   * Raw-bytes lane for binary assets (images) opened in viewer panes.
   * Unlike /local-file this IS sandboxed and resolves exactly like /read
   * (tilde expansion, flavor-aware normalization, allowedFilePaths → 403);
   * sendFile supplies the extension-based Content-Type (image/png, ...).
   */
  router.get('/raw', validatePath, async (req, res) => {
    const filePath = req.query.path as string
    if (!filePath) {
      return res.status(400).json({ error: 'path query parameter required' })
    }

    const resolved = await resolveUserFilesystemPath(filePath)

    try {
      const stat = await fsp.stat(resolved)
      if (stat.isDirectory()) {
        return res.status(400).json({ error: 'Cannot read directory' })
      }
    } catch (err: any) {
      if (err.code === 'ENOENT') {
        return res.status(404).json({ error: 'File not found' })
      }
      return res.status(500).json({ error: err.message })
    }

    await new Promise<void>((resolve) => {
      res.sendFile(resolved, (error?: NodeJS.ErrnoException) => {
        if (error && !res.headersSent) {
          if (error.code === 'ENOENT') {
            res.status(404).json({ error: 'File not found' })
          } else {
            res.status(500).json({ error: 'Failed to send file' })
          }
        }
        resolve()
      })
    })
  })
```

```rust
/// `GET /api/files/raw?path=<p>` → raw bytes with the send-compatible
/// Content-Type table (port of the Node `/api/files/raw` route in
/// `server/files-router.ts`).
///
/// Unlike `/local-file` (deliberately unsandboxed for Browser-pane `file://`
/// entries), this route resolves exactly like [`read_file`]: tilde
/// expansion, flavor-aware normalization, and the live `allowedFilePaths`
/// sandbox (403). Error shapes mirror `read_file` (`400"Cannot read
/// directory"`, `404 "File not found"`); the byte lane reuses
/// [`send_file_response`], so image extensions come back with their vendored
/// `image/*` Content-Type — the pane viewer's render hook.
async fn raw_file(
    State(state): State<FilesState>,
    headers: HeaderMap,
    Query(q): Query<PathQuery>,
) -> Response {
    if !crate::boot::is_authed(&headers, &state.auth_token) {
        return unauthorized();
    }
    let Some(path) = q.path.filter(|p| !p.is_empty()) else {
        return bad_request("path query parameter required");
    };
    let resolved = resolve_user_path(&path);
    let settings = state.settings.get().await;
    if !is_path_allowed(
        resolved.sandbox_target(),
        settings.allowed_file_paths.as_deref(),
    ) {
        return forbidden();
    }
    // Node's toFilesystemPath fallthrough — see read_file.
    let resolved = resolved.fs_path.unwrap_or(resolved.display);
    match std::fs::metadata(&resolved) {
        Ok(meta) if meta.is_dir() => bad_request("Cannot read directory"),
        Ok(meta) => match std::fs::read(&resolved) {
            Ok(bytes) => send_file_response(&resolved, &meta, bytes),
            Err(err) if err.kind() == std::io::ErrorKind::NotFound => not_found("File not found"),
            Err(err) => internal_error(&err.to_string()),
        },
        Err(err) if err.kind() == std::io::ErrorKind::NotFound => not_found("File not found"),
        Err(err) => internal_error(&err.to_string()),
    }
}
```
