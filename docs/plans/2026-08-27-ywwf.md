Observed while verifying freshopencode-db-history: test/e2e-browser/specs/opencode-restart-recovery.spec.ts has pre-existing failures where restored terminal OpenCode panes use a stale /tmp/freshell-e2e-* initialCwd after the TestServer home directory has been deleted. Expected: restored OpenCode terminal sessions should validate or refresh initialCwd before restart/config injection, falling back to a live workspace/home when the persisted cwd no longer exists.

### Explicit constraints
- Suggested coverage: preserve or add an e2e regression around opencode-restart-recovery with a deleted prior home/cwd and assert restart recovery succeeds without cwd-missing MCP injection errors.

### Accepted tradeoffs and residuals
- (none stated)

**Goal:** After a Freshell server restart, a replayed terminal pane whose persisted `initialCwd` no longer exists recovers successfully — the server falls back to a live default/home directory instead of dying in OpenCode MCP config injection with `PTY_SPAWN_FAILED`.

**Architecture:** The stale value enters the server once, at the `terminal.create` WebSocket handler: replayed creates (`restore: true` after reconnect, or `recoveryIntent: 'fresh_after_restore_unavailable'`) carry the client-persisted `cwd` verbatim into `TerminalRegistry.create` → `buildSpawnSpec` → `generateMcpInjection('opencode', …)`, whose `fs.existsSync(cwd)` guard throws. The fix validates the requested cwd at that single WS chokepoint — only for replayed creates — using the existing `isReachableDirectorySync` helper; an unreachable replayed cwd is dropped (structured warn log) so the registry's existing default chain (`getDefaultCwd(settings)` → `os.homedir()`) supplies a live directory. Interactive (non-replay) creates keep the deliberate clear-error behavior. The Rust server (`freshell-server`) has the identical hole at its `resolve_create_cwd` callsite and gets a parity fix. **Load-bearing validation falsified one planning assumption:** the target e2e spec is red at base on any host — fixture/tracker drift (commits `bbf3bad96` + `5dda73743`) starves the opencode session-ownership reducer of its busy signal, so `waitForOpenCodeSessions` can never pass and the kata's regression has no working vehicle. The plan therefore begins with the empirically-verified repair (prerequisite Task 1: env-gated busy-at-launch emulation in the fake fixture + opt-in from this spec), then layers the product fix and the new regression test on top.

**Tech Stack:** Node.js/TypeScript (ws-handler, terminal-registry, path-utils), Rust (crates/freshell-ws terminal create path), Vitest (server-config WS tests with FakeRegistry), Playwright (opencode-restart-recovery e2e, local lane only), cargo test.

```ts
/**
 * Replayed creates (restore after a server restart, or fresh recovery after a
 * restore became unavailable) carry the client-persisted pane `initialCwd`,
 * which can point at a directory that no longer exists (for example a prior
 * server's HOME). Passing it through verbatim dies later in provider spawn
 * prep — OpenCode MCP config injection throws `cwd directory does not exist`
 * and the pane never recovers. Interactive creates keep the deliberate
 * clear-error behavior, so validation is scoped to replays: an unreachable
 * replayed cwd is dropped here and the registry's default chain
 * (configured defaultCwd → home) supplies a live directory instead.
 */
function resolveReplayedCreateCwd(input: {
  cwd: string | undefined
  restoreRequested: boolean
  recoveryIntent: 'fresh_after_restore_unavailable' | undefined
}): { cwd: string | undefined; droppedStaleCwd: string | undefined } {
  if (!input.cwd) return { cwd: input.cwd, droppedStaleCwd: undefined }
  const replayed = input.restoreRequested || input.recoveryIntent != null
  if (!replayed) return { cwd: input.cwd, droppedStaleCwd: undefined }
  if (isReachableDirectorySync(input.cwd).ok) return { cwd: input.cwd, droppedStaleCwd: undefined }
  return { cwd: undefined, droppedStaleCwd: input.cwd }
}
```

```rust
/// Replayed creates (restore after a server restart, or fresh recovery after
/// a restore became unavailable) carry the client-persisted pane
/// `initialCwd`, which can point at a directory that no longer exists (a
/// prior server's HOME, a deleted project dir). Parity with the Node server
/// (ws-handler `resolveReplayedCreateCwd`): an unreachable replayed cwd is
/// dropped so the `resolve_create_cwd` ladder (defaultCwd → home) supplies a
/// live directory, instead of dying in OpenCode MCP config injection.
/// Interactive creates keep the deliberate clear-error behavior.
#[derive(Debug)]
enum ReplayedCreateCwd {
    Keep(Option<String>),
    DroppedStale { original: String },
}

fn resolve_replayed_create_cwd(
    explicit: Option<&str>,
    restore: Option<bool>,
    recovery_intent: Option<&str>,
) -> ReplayedCreateCwd {
    let replayed = restore == Some(true) || recovery_intent.is_some();
    match explicit {
        Some(cwd) if replayed
            && !cwd.is_empty()
            && !std::fs::metadata(cwd).map(|meta| meta.is_dir()).unwrap_or(false) =>
        {
            ReplayedCreateCwd::DroppedStale { original: cwd.to_string() }
        }
        other => ReplayedCreateCwd::Keep(other.map(|cwd| cwd.to_string())),
    }
}
```
