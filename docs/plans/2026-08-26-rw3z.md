## Root Cause (empirically established; drives the whole plan)

1. **Local reproduction** (this worktree, `npx playwright test --config test/e2e-browser/playwright.config.ts --project=rust-chromium specs/mcp-bridge-rust.spec.ts`): the spec fails at line 130 with `Expected: "09bf01e5-…" Received: undefined`. Line 129 `expect(ourPane).toBeTruthy()` **passes** — the pane row IS present in the bare `list-panes` result, findable by `id`. The kata's gloss ("the pane never appears in the queried surface") is inaccurate: the pane appears; the failing datum is solely the per-row `tabId` cross-reference field. All earlier steps (new-tab, list-tabs, send-keys, wait-for, capture-pane) pass, so there is no publication or timing defect and no "missing wait-for-panes-visible step".
2. **Contract history.** When the spec was authored (`18ad65494`, 2026-07-18), the Rust `GET /api/panes` handler emitted `"tabId": t.id` per row (visible in `git show 18ad65494:crates/freshell-freshagent/src/terminal_tabs.rs`), so the assertion passed. During the AUTO-01/AUTO-06 LayoutStore work, the row contract evolved; the df1→main sync merge (`docs/plans/df1-evidence/MAIN-SYNC-MERGE.md`, "Gate record") records the resolution deliberately: "main's evolved Node-exact listPanes row contract: no `tabId`" — pinning `9b2ee0709` green under that contract. Today's row builder (`crates/freshell-freshagent/src/terminal_tabs.rs:2324-2356`, on `layout_store.rs:611-651`) emits the Node-exact `{id, index, kind?, terminalId?, title?}` — byte-for-byte the frozen Node server's shape (`server/agent-api/layout-store.ts:341-355`, `listPanes`). The branch-stage note in `docs/plans/df1-evidence/AUTO-01.md` ("additive `tabId` KEPT — one recorded deviation") is superseded history, left in place as an append-only campaign record; `MAIN-SYNC-MERGE.md` already records the override, so no doc edit is owed.
3. **No consumer needs `tabId` in the row.** The frozen MCP binary's `PaneSummary` (`server/mcp/freshell-tool.ts:146`) types `{id, index?, kind?, terminalId?, title?}` and its `list-panes` passes rows through unread; the CLI (`server/cli/index.ts:512-527`) prints those five fields; the later full-matrix pin (`mcp-qa-smoke-rust.spec.ts`) always queries with a tab `target` and never reads `tabId`. Cross-referencing pane→tab on this surface is done via the `?tabId=` filter, which the frozen binary exercises as `list-panes`'s `target` param (it resolves the tab via `GET /api/tabs`, then queries `GET /api/panes?tabId=<id>`; the Rust store answers explicit-tab queries across all client snapshots, `layout_store.rs:616-623`).

**Conclusion (answers the kata's question directly):** the product is NOT wrong; the test's query/assertion surface is wrong. Fix the test.

- [ ] **Step 2: Apply the test-alignment edit**

Replace the block quoted above with:

```ts
      // -- list-panes: our pane is present in the bare listing, correctly
      // cross-referenced to its terminal. The pinned row contract is the
      // Node-exact `{id, index, kind?, terminalId?, title?}` — deliberately
      // WITHOUT a per-row `tabId` (the df1->main sync merge adopted main's
      // evolved Node-exact listPanes row contract; see
      // docs/plans/df1-evidence/MAIN-SYNC-MERGE.md "Gate record"). The frozen
      // MCP binary types the same five fields (`PaneSummary`,
      // server/mcp/freshell-tool.ts) and never reads `tabId`. Tab membership
      // is cross-referenced the way this surface actually offers it: the
      // `?tabId=` filter, exercised via the MCP tool's `target` param below.
      const listPanes = await mcp.callFreshellAction('list-panes')
      expect(listPanes.status).toBe('ok')
      const ourPane = (
        listPanes.data.panes as Array<{ id: string; index: number; kind?: string; terminalId?: string }>
      ).find((p) => p.id === paneId)
      expect(ourPane).toBeTruthy()
      expect(ourPane?.terminalId).toBe(terminalId)
      expect(ourPane?.kind).toBe('terminal')
      expect(ourPane?.index).toBe(0)

      // -- list-panes with the tab as target: the pane<->tab membership edge --
      const tabPanes = await mcp.callFreshellAction('list-panes', { target: tabId })
      expect(tabPanes.status).toBe('ok')
      const tabPaneIds = (tabPanes.data.panes as Array<{ id: string }>).map((p) => p.id)
      expect(tabPaneIds).toContain(paneId)
```

Notes for the implementer:

- This is the complete replacement text; preserve surrounding code and the file's existing formatting conventions (2-space indent inside the test callback).
- `target: tabId` is honored by the frozen binary: `list-panes`'s `target` resolves a TAB by id-or-title (`resolveTabTarget`) and issues `GET /api/panes?tabId=<id>` — the `mcp-qa-smoke-rust.spec.ts` matrix pin already drives exactly this call shape successfully.
- The strengthened bare-listing assertions (`terminalId`, `kind`, `index`) keep the pin's teeth: each can still fail independently if the pane is absent, mis-cross-referenced to a terminal, or mis-indexed.
