### Requested result

Fix the production gap behind kata freshell#des0: `CodexRemoteProxy.start()`
(`server/coding-cli/codex-app-server/remote-proxy.ts`) calls its port allocator
exactly once and does not retry when the preallocated loopback port is lost
before the proxy binds, even though `allocateLocalhostPort`

fix lives in production code rather than only in test harnesses. Observed live
evidence of the gap: an unrelated remote-proxy test failed under load with
`Error: listen EADDRINUSE: address already in use 127.0.0.1:42935` during the

### Accepted tradeoffs and residuals

- The retry is bounded by a small fixed default (mirroring the runtime's
  `DEFAULT_STARTUP_ATTEMPT_LIMIT = 2`), not unbounded: if every attempt loses
  the port race, the proxy fails loudly with an aggregate error rather than
  masking systemic resource exhaustion behind endless retries.
- The f3wp harness-side retry loop in the test helper becomes redundant once
  production retries; it is removed as part of this work so every existing
  call site exercises the production path (verified by the unchanged full
  remote-proxy suite passing with the band-aid removed).
- No end-user-visible surface changes: no `README.md` or `docs/index.html`
  updates are required.

**Goal:** `CodexRemoteProxy.start()` honors `allocateLocalhostPort`'s
documented retry contract in production, eliminating the lost-port EADDRINUSE
flake class for every current and future proxy call site.

**Architecture:** Inside `CodexRemoteProxy.start()`, wrap the existing
allocate-then-bind sequence in a bounded retry loop driven by a new
`startupAttemptLimit` option (default 2, mirroring `CodexAppServerRuntime`).
Each attempt allocates a FRESH endpoint, tries to bind a `WebSocketServer` to
it, and on failure resets instance state, closes the failed server, records
the error, logs a structured warning, and retries; after the final attempt it
throws an aggregate error carrying the attempt count and the last cause.
Test harness changes then strip the f3wp band-aid so the whole existing suite
pins the production behavior.

**Tech Stack:** Node.js, TypeScript (NodeNext/ESM), `ws` `WebSocketServer`,
Vitest (repo-coordinated `npm run test:vitest -- ...` path, server config).

4. Replace the body of `start()` (lines 212-236) with the retry loop. The
loop mirrors `runtime.ts:1818`'s shape: allocate a fresh endpoint per attempt
(the allocator call itself is outside the try, so allocator failures propagate
immediately — same as the runtime), retry any bind failure, clean up failed
state between attempts, and throw an aggregate error after the final attempt:

```typescript
  async start(): Promise<{ wsUrl: string }> {
    if (this.server) return { wsUrl: this.wsUrl }
    let lastError: Error | undefined
    for (let attempt = 1; attempt <= this.startupAttemptLimit; attempt += 1) {
      // allocateLocalhostPort's reservation is best-effort (local-port.ts):
      // the race between closing its probe socket and our rebind can lose the
      // port, so every attempt allocates a FRESH endpoint before binding.
      const endpoint = await this.portAllocator()
      try {
        await new Promise<void>((resolve, reject) => {
          const server = new WebSocketServer({
            host: endpoint.hostname,
            maxPayload: this.maxRawForwardBytes,
            port: endpoint.port,
          }, () => resolve())
          server.once('error', reject)
          server.on('connection', (client) => this.handleClientConnection(client))
          this.server = server
          this.endpoint = endpoint
        })
        break
      } catch (error) {
        lastError = error instanceof Error ? error : new Error(String(error))
        const failedServer = this.server
        this.server = null
        this.endpoint = null
        if (failedServer) {
          await new Promise<void>((resolve) => failedServer.close(() => resolve()))
        }
        log.warn({
          err: lastError,
          attempt,
          startupAttemptLimit: this.startupAttemptLimit,
        }, 'Codex remote proxy loopback bind attempt failed')
      }
    }
    if (!this.server) {
      const startupError = new Error(
        `Failed to start Codex remote proxy on a loopback endpoint after ${this.startupAttemptLimit} attempts: ${lastError?.message ?? 'unknown error'}`,
      )
      startupError.cause = lastError
      throw startupError
    }
    if (this.requireCandidatePersistence) {
      this.ensureCandidateCaptureTimer()
    }
    log.info({
      wsUrl: this.wsUrl,
      upstreamWsUrl: this.upstreamWsUrl,
      requireCandidatePersistence: this.requireCandidatePersistence,
      maxRawForwardBytes: this.maxRawForwardBytes,
    }, 'Codex remote proxy listening')
    return { wsUrl: this.wsUrl }
  }
```

Notes for the implementer:
- `startupError.cause = lastError` uses property assignment (identical to the
  proven sibling pattern at `launch-planner.ts:116`), not the ES2022 options
  bag, so no tsconfig lib question arises.
- `failedServer.close(cb)` after a failed listen: Node's `http.Server.close`
  invokes the callback (with an `ERR_SERVER_NOT_RUNNING` error argument) even
  when the server never bound, so the await terminates; the negative tests in
  this task prove it empirically.

async function startProxy(upstreamWsUrl: string, options: {
  requestHoldTimeoutMs?: number
  candidateCaptureTimeoutMs?: number
  requireCandidatePersistence?: boolean
  maxRawForwardBytes?: number
  portAllocator?: () => Promise<LoopbackServerEndpoint>
} = {}): Promise<CodexRemoteProxy> {
  // CodexRemoteProxy.start() retries lost-port binds internally
  // (startupAttemptLimit, mirroring CodexAppServerRuntime) per
  // allocateLocalhostPort's documented contract (server/local-port.ts), so
  // this helper deliberately makes exactly ONE start() attempt: every call
  // site in this file exercises the production retry path, and the f3wp
  // harness-side retry band-aid is gone.
  const proxy = new CodexRemoteProxy({ upstreamWsUrl, ...options })
  try {
    await proxy.start()
  } catch (error) {
    await proxy.close().catch(() => {})
    throw error
  }
  proxies.add(proxy)
  return proxy
}
